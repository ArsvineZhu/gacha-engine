# 执行算法与性能

优化目标是在保持规则语义、精确单步概率与种子重放的前提下，减少每次抽样和分析的重复工作。解释器保留为基线，SDK 与 CLI 默认使用准备执行器。

## 概率计划与状态更新分离

解释器为全部候选计算下一状态，再选择一个结果。准备执行器先取得精确概率计划，抽样后只执行选中结果的更新与事件。完整动作仍原子提交，失败时状态与随机数进度回滚。

候选顺序和整数拒绝采样保持一致。条件抽样概率在计划生成时计算，后续直接使用，因此不再为每次随机试验重复进行相同的有理数除法。

## 编译与缓存

准备阶段展开静态池和加权选择器。具有有限上界的概率参数在上界不超过 4096 时生成精确数值表；其他参数保留表达式求值。不能预先求值的表项在实际读取时按原语义处理，强制条目保底仍跳过不需要的概率表达式。

概率计划的缓存键由卡池、动作、概率参数的精确值，以及保底和条件选择器的真值构成。它保存的是当前抽取分布，不保存完整下一状态。奖励进度、事件条件和更新始终从实时完整状态读取。

这种投影比直接缓存计数器值更有效：软保底之前的不同计数可以产生相同基础概率；未到 120 次的当期进度可以产生相同保底决策。仅在这些决策与数值均相同时复用计划。

缓存最多 4096 个计划，到达上限后清空重建；清空不影响概率和状态语义。`preparation` 返回静态表数、数值表数、命中、缺失和清空次数。规则由执行器不可变持有，多个会话共享准备结果，但状态独立。

## 分析中的等价分支合并

分析按“目标是否命中”和“所有抽后结果条件的真值”划分候选。类内条目触发相同更新和事件，其概率先以有理数相加，只执行一次状态转移。

正确性依据是：相同抽前状态下，若全部结果条件的真值一致，声明顺序相同的更新与事件必然一致；目标命中也一致时，到达时间分析无法区分类内条目。这是保守的局部等价分支合并，未任意合并不同历史状态。

理论参考：[Stark 的概率行为等价与概率双模拟论文](https://www3.cs.stonybrook.edu/~stark/REPORTS/bisimulation.pdf)。本实现使用规则结构直接构造充分条件，不执行全局最小化算法。

## 候选方案的取舍

[Keith Schwarz 的离散抽样算法说明](https://www.keithschwarz.com/darts-dice-coins/)比较累积概率、树与 Alias 方法。Alias 可降低固定分布的抽样复杂度，但需要额外构建和表示，并改变随机数消费方式。

当前瓶颈首先来自为每个候选复制状态和执行规则。优先减少这些工作，再缓存精确条件抽样概率，已经取得可测收益。因此当前未增加 Alias 或浮点概率表。

后续优化可针对仍然存在的成本开展：将执行中的字符串槽位改为稠密状态向量，在接口边界保留稳定字符串表示；按实际工作负载评估别名采样；对更大的分析图研究满足等价条件的状态聚合。是否采用由剖析和差分结果决定。

## 测量口径

```sh
cargo run --manifest-path examples/performance/Cargo.toml --release --locked
```

基准使用角色与武器两个代表场景，1000 次独立账户模拟，每项重复三次取中位数。解释器与准备执行器在相同初始状态、种子和规则下比较。分析逐点 CDF 容差为 `1e-12`，模拟逐抽频数必须完全一致。

计时覆盖完整分析或完整模拟，不包含编译。报告同时保留原始毫秒、倍率和缓存统计；准备执行器在重复测量中包含缓存复用，所以结果代表同一引擎连续服务的工作负载。初始化成本不包含在倍率内。

本地测量记录见[性能数据](../examples/performance/reports/performance.json)，第三方接入结果见[SDK 报告](../examples/sdk/endfield-danqingdu/REPORT.md)。不同机器与规则规模的收益需重新测量。
